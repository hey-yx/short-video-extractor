## 一、逐项目调研

### 1. yt-dlp（yt-dlp/yt-dlp）
- **定位**：全网视频下载的事实标准 CLI/库，1000+ 站点 extractor，YouTube 维护最深（Innertube 多 client、PO Token、SABR）。
- **活跃度**：202,911 stars，最近 push 2026-10-26（发布 2026.10.26），日更级维护（来源：https://api.github.com/repos/yt-dlp/yt-dlp 、https://github.com/yt-dlp/yt-dlp/releases）。License：Unlicense（公有领域，可直接搬代码）。
- **值得借鉴的具体技术点**：
  1. **PO Token Provider 可插拔框架**：`yt_dlp.extractor.youtube.pot.provider` 定义 `PoTokenProvider` 抽象类 + `register_provider`/`register_preference` 注册与优先级排序，provider 声明 `_SUPPORTED_CLIENTS`、`_SUPPORTED_CONTEXTS`（GVS/Player/Subs）、`is_available()`，核心只依赖三个公开 API（cache/provider/utils）。签名（token）生成被完全外置成第三方插件（如 bgutil-ytdlp-pot-provider、yt-dlp-getpot-wpc），算法过期时用户换插件而非等主仓库更新。（来源：https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/pot/README.md 、https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide）
  2. **Token 作用域/绑定与生命周期管理**：PO Token 按平台（BotGuard/DroidGuard/iOSGuard 不可互用）、按场景（GVS/Player/Subs）、按绑定对象（VisitorID/SessionID/视频 ID）区分，绑定视频 ID 的 token 每视频一个、寿命可能短至 12 小时——即"token 是易耗品，必须按作用域缓存并定期重铸"。（来源：https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide）
  3. **按 client 绕过而非硬扛**：官方表格列出每个 Innertube client 的 PO Token 要求，`tv`/`web_embedded`/`android_vr` 不需要 GVS PO Token，`web_safari` 的 HLS (m3u8) 当前不需要 GVS PO Token；用 `player_client` extractor-arg 切 client 即可绕开 token 与 403。（来源：https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide）
  4. **防限流参数体系**：`--sleep-requests`（提取阶段请求间隔）、`--sleep-interval/--max-sleep-interval`（下载前随机 sleep）、`--retry-sleep [TYPE:]EXPR` 支持 linear/exp 指数退避且按 http/fragment/file_access/extractor 分类、`--extractor-retries`（已知 extractor 错误单独重试）、`--throttled-rate`（检测到限速即重新解析直链）、`--http-chunk-size`（分块下载绕带宽限速）。（来源：https://github.com/yt-dlp/yt-dlp/blob/2026.08.19/README.md 、https://manpages.debian.org/trixie/yt-dlp/yt-dlp.1.en.html）
  5. **限流阈值量化**：官方 wiki 给出实测数字（guest ~300 视频/小时、账号 ~2000 视频/小时），并建议下载间隔 5-10 秒（`-t sleep`）。（来源：https://github.com/yt-dlp/yt-dlp/wiki/extractors）

### 2. Evil0ctal/Douyin_TikTok_Download_API
- **定位**：自托管抖音/TikTok/B 站数据 API（FastAPI + PostgreSQL/TimescaleDB + Redis + React 控制台 + MCP server），核心卖点是"自我维护的身份池"（cookies+指纹+代理绑定），原生 Python 实现 a_bogus/X-Bogus/TikTok 签名/B 站 WBI，无头浏览器只作兜底和**签名漂移检测器**。
- **活跃度**：20,942 stars，最近 push 2026-10-27（当日），文档体系 18 篇完整。License：Apache-2.0（可搬代码，保留 NOTICE 即可）。（来源：https://api.github.com/repos/Evil0ctal/Douyin_TikTok_Download_API 、https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/llms.txt）
- **值得借鉴的具体技术点**：
  1. **身份池状态机**：身份=cookie 罐+浏览器指纹+代理绑定+历史，四者终身绑定不重组（cookie 不换出口 IP、不换 UA）；状态 `active/cooling/degraded/retired`，失败连击 `consecutive_fails` 只被一次成功清零，冷却时间 `base(60s) × 2^(streak-1) × risk_weight` 上限 6 小时，触顶转 degraded。（来源：https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/06-identities-and-proxies.md）
  2. **健康分调度**：`health = success_rate × (1 - risk_rate) × 0.5^consecutive_fails`，15 分钟/60 分钟双窗口，样本不足用先验 0.8，评分分 5 桶再排序（避免最健康身份成热点），每身份并发固定 1。
  3. **失败四分类**：`ok / business_error / risk_control / network_error`——**business_error（作品已删/私密）对身份零影响、不进熔断**；network_error 只加连击不冷却；只有 risk_control 才冷却。这直接决定熔断器误伤率。（来源：https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/04-concepts.md）
  4. **铸造节流**：pool_filler 每 tick 只铸 1 个身份、Redis 跨进程锁防并发铸造、按路线指数退避（60s→3600s）；"5 个新访客一秒内出现"本身就是风控信号；usable 数为 0 时暂停铸造（避免往火里添新号）。
  5. **指纹-传输层一致性**：UA 必须带浏览器家族+主版本，TLS profile 按主版本精确匹配（漂移≤2 版本 ok、≤4 警告、>4 拒绝），Firefox UA 套 Chrome TLS 视为"最响亮的自曝"直接拒绝入库。（来源：https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/04-concepts.md）
  6. **端点级熔断与探测分离**：诊断命令（`dtk fetch`/identity probe）绕过调度器/令牌桶/缓存，避免探测本身污染池状态；每端点有 circuit window。B 站游客会话可用一个纯 HTTP 请求（`/x/frontend/finger/spi`）铸造，无需浏览器。

### 3. JoeanAmier/TikTokDownloader（现名 DouK-Downloader）+ 同作者 XHS-Downloader / KS-Downloader
- **定位**：抖音/TikTok 作品下载与数据采集（含 Web API、评论、直播拉流、增量下载）；XHS-Downloader 13,128 stars 专做小红书，KS-Downloader 做快手。
- **活跃度**：TikTokDownloader 17,136 stars，push 2026-09-22；XHS-Downloader push 2026-10-23（活跃）。License：两者均 **GPL-3.0**。注意 TikTokDownloader README 明示"**加密参数算法不再维护**，如因平台更新导致功能异常请自行准备加密参数生成代码"（配 encipher_example.py 外挂方案）。（来源：https://api.github.com/repos/JoeanAmier/TikTokDownloader 、https://github.com/JoeanAmier/TikTokDownloader 、https://api.github.com/repos/JoeanAmier/XHS-Downloader 、https://github.com/JoeanAmier/XHS-Downloader）
- **值得借鉴的具体技术点**：
  1. **签名算法外置（encipher）**：把法律/维护敏感的加密参数生成从主仓库剥离，做成"用户自备生成代码 + 配置接入点"，主项目只维护解析与下载。这是"算法会过期"的合规与解耦双解。
  2. **curl_cffi TLS 伪装**：Web API 调用示例直接用 `curl_cffi.requests.post`，即请求走浏览器级 TLS/JA3 指纹（见第 6 条）。
  3. **下载健壮性细节**：断点续传、文件完整性处理、已下载 ID 落库自动跳过、多线程下载、XHS-Downloader 的"作品链接带日期/ xsec_token，旧日期链接易被风控，应使用最新获取的链接"提示（直链/分享链时效问题的一手证据）。（来源：https://github.com/JoeanAmier/XHS-Downloader ）
  4. **MCP/API 双模式**：XHS-Downloader 与 Evil0ctal 都提供 MCP server（AI agent 直接调用），是此类服务的新标配接口形态。

- **定位**：Python 多平台下载库（Douyin/TikTok/Twitter/Weibo），接口数据处理层清晰，功能矩阵（直播流、弹幕 WSS 转发、合集）全。

- **值得借鉴的具体技术点**：
  1. **纯 HTTP 令牌工厂**：`TokenManager.gen_real_msToken / gen_false_msToken / gen_ttwid / gen_webid`，`VerifyFpManager.gen_verify_fp / gen_s_v_web_id`——会话令牌用算法生成而非浏览器铸造，直接命中我们"uifid 需重铸"的痛点（uifid 同类思路：找平替生成/延寿方式）。

### 6. 补充发现：curl_cffi / curl-impersonate（lexiforest/curl_cffi，TikTokDownloader 与 Evil0ctal 都在用）
- **定位**：浏览器 TLS/JA3/HTTP2 指纹伪装 HTTP 客户端（BoringSSL 重放 Chrome ClientHello、HTTP/2 SETTINGS/WINDOW_UPDATE/伪头顺序、默认头与 UA 一致），支持 chrome99–chrome142 等预设与 ja3/akamai/extra_fp 自定义。
- **关键事实**：风控系统在 TLS 握手层（JA3/JA4）就识别非浏览器客户端，头伪装无效；UA 与 impersonate 预设不匹配是"最致命错误"；官方明示**不要随机生成 JA3**（站点用 allowlist，随机指纹必挂）。（来源：https://github.com/lexiforest/curl_cffi 、https://curl-cffi.readthedocs.io/en/v0.11.1/impersonate.html 、https://krowdev.com/note/tls-fingerprinting-curl-cffi）
- **对我们的意义**：L2 纯 HTTP 签名通道（Bun fetch）的 TLS 指纹天然暴露自动化特征，是风控命中率的隐性上限。

## 二、优化建议清单（按优先级）

### P0-1 签名/令牌生成"提供者化"，算法过期热替换
- **针对局限**：签名算法会过期、uifid 需重铸。
- **同类做法**：yt-dlp 的 PO Token Provider 框架——抽象 `SignerProvider` 接口（声明支持的平台/通道/场景、`is_available()`），注册表+优先级排序，主干只留接口；TokenDownloader 的 encipher"用户自备生成代码"则是把敏感算法完全外置。
- **落地**：把 abogus/x-s/x-bogus 实现从 platforms/ 内抽成 `signers/` 插件（每个含版本号+自检请求），算法失效时单换插件或热加载外部 JS；浏览器铸造 uifid 也做成 provider（纯 HTTP 优先、浏览器兜底）。
- **代价**：中（接口抽象 + 2~3 天迁移）；来源：https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/youtube/pot/README.md 、https://github.com/JoeanAmier/TikTokDownloader

### P0-2 失败分类进熔断逻辑：业务错误不算风控
- **针对局限**：风控止血窗口/熔断粘性误伤（已删/私密作品被当风控，触发 45s 止血与 60s 粘性降级）。
- **同类做法**：Evil0ctal 四分类 `ok/business_error/risk_control/network_error`，business_error 对身份零影响、不进冷却；network_error 只加连击不冷却；仅 risk_control 算熔断。
- **落地**：在响应分类器里区分"作品不存在/已设私密"（http 200 + 业务码）与风控特征（空字节/验证页/特定错误码），熔断计数只吃后者；负缓存对 business_error 用长 TTL、对 risk_control 用短 TTL。
- **代价**：小（纯逻辑改动）；来源：https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/04-concepts.md

### P0-3 uifid 铸造池化 + 节流
- **针对局限**：uifid 需重铸（每请求一次性浏览器铸造，成本高且"多号秒现"本身是风控信号）。
- **同类做法**：Evil0ctal 身份池——铸造一次终身绑定（cookie+指纹+代理不重组）、每 tick 只铸 1 个、指数退避、`active/cooling/degraded/retired` 状态机、健康分排序（`success_rate × (1-risk_rate) × 0.5^streak`，5 桶防热点）；f2 的 TokenManager 纯 HTTP 生成 ttwid/msToken/webid 尝试免浏览器。
- **落地**：uifid 改为池化复用（带冷却与失败连击），铸造限速 1 个/间隔；先试纯 HTTP 铸造（对照 B 站 `/x/frontend/finger/spi` 类似口子/ f2 令牌工厂思路），失败再上浏览器。
- **代价**：中；来源：https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/06-identities-and-proxies.md 、https://github.com/Johnserf-Seed/f2

### P1-4 L2 通道接入 TLS 指纹伪装
- **针对局限**：风控命中（L2 纯 HTTP 签名通道被识别为自动化）。
- **同类做法**：curl_cffi/curl-impersonate 重放真实浏览器 ClientHello + HTTP/2 指纹，UA 与预设强一致（不一致=自曝）；TikTokDownloader、Evil0ctal 均采用（Evil0ctal 还按"指纹主版本→最近已知 TLS profile"匹配，漂移>4 拒绝）。
- **落地**：Bun 侧没有原生 impersonate——用 curl-impersonate/tls-client 子进程或 Go cycleTLS sidecar 发 L2 请求；按 uifid 对应 UA 选 impersonate 预设。注意：**不要随机伪造 JA3**，用预设。
- **代价**：中（引入 sidecar/子进程）；来源：https://github.com/lexiforest/curl_cffi 、https://curl-cffi.readthedocs.io/en/v0.11.1/impersonate.html

### P1-5 YouTube 中转流量减负：按 client 绕 PO Token + token 作用域缓存
- **针对局限**：YouTube 需走 /media HMAC 中转（直链绑 IP）。
- **同类做法**：yt-dlp client 矩阵——`tv`/`web_embedded`/`android_vr` 免 GVS PO Token，`web_safari` 的 HLS 当前免 PO Token；PO Token 绑视频 ID、寿命短（~12h），按作用域（GVS/Player/Subs）分别缓存、到期重铸；官方还给出 guest ~300 视频/h 的限流实测。
- **落地**：/media 中转前优先选免 token/可直连的 client 出口（HLS m3u8 直链做 Range 透传而非整段代理）；token 按 (client, 场景, 视频ID) 三元组缓存并设 12h TTL；命中限流阈值前主动换 client。
- **代价**：中；来源：https://github.com/yt-dlp/yt-dlp/wiki/PO-Token-Guide 、https://github.com/yt-dlp/yt-dlp/wiki/extractors

### P1-6 直链时效：过期自动重解析 + 断点续传拼接
- **针对局限**：直链有时效（缓存命中后 403/404）。
- **同类做法**：yt-dlp `--throttled-rate`（检测限速即重新取直链）+ fragment 级重试；XHS-Downloader 断点续传、文件完整性处理、"旧日期分享链接会被风控应取最新链接"的一手经验。
- **落地**：/media 流式中转遇到非 2xx 时按 (分享链接, 缓存键) 自动重解析一次再 Range 续传（客户端无感）；LRU 直链缓存 TTL 分平台实测标注；负缓存与直链缓存分开短/长 TTL。
- **代价**：小；来源：https://github.com/yt-dlp/yt-dlp/blob/2026.08.19/README.md 、https://github.com/JoeanAmier/XHS-Downloader

### P1-7 请求级限速/退避分层
- **针对局限**：风控止血窗口粒度粗（现在是服务级 45s 一刀切）。
- **同类做法**：yt-dlp 的分类型 sleep/retry（`--sleep-requests`、`--retry-sleep exp=...`、extractor 独立重试次数）；Evil0ctal 每端点 circuit window + 令牌桶、每身份并发 1。
- **落地**：止血窗口下移到"平台×通道×端点"粒度；对平台请求加随机 jitter 间隔（参考 yt-dlp 5-10s 建议）与 exp 退避重试（仅对 network/风控类错误）。
- **代价**：小；来源：https://manpages.debian.org/trixie/yt-dlp/yt-dlp.1.en.html 、https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/04-concepts.md

### P2-8 浏览器兜底从"截包"升级为"页内调签名函数"
- **针对局限**：签名算法过期时 L3 兜底效率低。
- **同类做法**：MediaCrawler"playwright 桥"——保留登录态浏览器上下文，`page.evaluate` 直接调用平台页面自己的签名 JS 拿参数（免逆向），CDP 复用既有 Chrome 免冷启动。
- **落地**：L3 浏览器实例常驻（browser-rpc 模式，参考 Evil0ctal `DTK_BROWSER_RPC_URL` 长驻服务而非每调用冷启动），在页内执行签名函数取 x-s/a_bogus，供 L2 离线发请求；配合 P0-1 的 provider 接口作为"自愈 provider"。
- **代价**：中（仅思路参考，MediaCrawler 代码 License 禁止搬用）；来源：https://github.com/kkeenee/NanmiCoder-MediaCrawler 、https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/documents/en/04-concepts.md

### P2-9 签名漂移检测器
- **针对局限**：签名算法过期（发现滞后）。
- **同类做法**：Evil0ctal 把无头浏览器同时用作"drift detector"（原生签名与浏览器实测比对，提前发现算法漂移）；yt-dlp provider 的 `is_available()` 自检。
- **落地**：定时用浏览器实测通道对同一分享链接解析，与 L2 结果比对，不一致即打 `signer_drift` 指标告警（Prometheus 已有 /metrics 直接加 counter）。
- **代价**：小；来源：https://github.com/Evil0ctal/Douyin_TikTok_Download_API/blob/main/llms.txt

### P2-10 解析层 filter/原始数据双视图
- **针对局限**：平台字段变更导致解析脆断。
- **同类做法**：f2 的 filter 类 + `_to_raw` 回溯原始响应。
- **落地**：platforms/ 解析结果保留原始 payload 引用（存缓存或采样日志），字段变动时可离线回放适配，不必等线上报错。
- **代价**：小；来源：https://github.com/Johnserf-Seed/f2

## 三、明确不建议抄的方向

1. **MediaCrawler 的代码**：NON-COMMERCIAL LEARNING LICENSE 1.1，仅限非商业学习研究、禁止商用与大规模爬取；我们是开源 HTTP 服务，搬代码即违约侵权。只可参考"playwright 桥取参数"思路并自行实现。（https://github.com/NanmiCoder/MediaCrawler/blob/main/LICENSE ）
2. **TikTokDownloader / XHS-Downloader / KS-Downloader 的代码**：GPL-3.0，代码并入会传染整个仓库为 GPL，与我们现有 License（非 GPL）冲突。只可参考架构与做法（encipher 外置、断点续传、curl_cffi 选型）。（https://github.com/JoeanAmier/TikTokDownloader ）
3. **整体照搬 Evil0ctal 的重架构**：PostgreSQL+TimescaleDB+Redis+React 控制台+browser-rpc，运维成本远超一个解析 HTTP 服务的定位；只取状态机、失败四分类、健康分、铸造节流四个轻量机制（其代码为 Apache-2.0，可搬但注意保留 NOTICE）。
4. **随机伪造 JA3/自造 TLS 指纹**：curl_cffi 文档明确站点按 allowlist 过滤，随机指纹只会更显眼；必须用真实浏览器预设且与 UA 严格一致。（https://curl-cffi.readthedocs.io/en/v0.11.1/impersonate.html ）
5. **抄 TikTokDownloader 的"签名算法停止维护、让用户自备"作为长期方案**：合规隔离可取（做成外挂插件），但直接弃维护等于放弃"开箱即用"卖点，会流失用户；应做成"主仓插件 + 外部 provider 兜底"两层。
6. **引用 SocialSingerDownloader**：检索不到可核实来源，不做无据引用。
