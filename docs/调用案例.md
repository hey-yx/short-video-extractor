# 调用案例

面向调用方：怎么发请求、返回长什么样、每个场景下该拿哪个字段、出错怎么处置。字段释义见 README 的 [API](../README.md#api) 一节，本文只讲用法。

下文统一 `BASE=http://127.0.0.1:7777`（换成你的服务地址即可）。示例响应取自仓库 `tests/fixtures/` 的真实抓取数据，**直链都有时效，照结构接、别照抄地址**。

三条先说在前面：

1. **下载直链不要带 Referer**。带本站或平台 Referer 反而会被 CDN 拦（小红书尤其明显）。`/media` 中转链接例外，它由服务端负责请求头。
2. **直链有过期时间**。`data.expiresAt` 是最早过期的时刻（Unix 秒），过了重新解析一次，不要长期缓存直链。
3. **同一条链接重复解析会命中缓存**，响应顶层的 `cached` 为 `true`。缓存不产生上游请求，放心重试。

### JavaScript（Node 18+ / Bun / Deno，原生 fetch）

```js
const BASE = 'http://127.0.0.1:7777';

async function parse(url) {
  const res = await fetch(`${BASE}/parse`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ url }),
    signal: AbortSignal.timeout(20_000),
  });
  const body = await res.json();
  // 出错时 HTTP 状态码非 2xx，信封在响应体里，状态码只作参考
  if (!body.success) {
    const err = new Error(`${body.error.code}: ${body.error.message}`);
    err.code = body.error.code;
    throw err;
  }
  return body.data;
}

const data = await parse('https://v.douyin.com/xxxxxxx/');
console.log(data.title, data.assets[0].url, new Date(data.expiresAt * 1000));
```

### Python（标准库，零依赖）

```python
import json
import urllib.request

BASE = "http://127.0.0.1:7777"


def parse(url: str) -> dict:
    req = urllib.request.Request(
        f"{BASE}/parse",
        data=json.dumps({"url": url}).encode(),
        headers={"Content-Type": "application/json"},
    )
    try:
        with urllib.request.urlopen(req, timeout=20) as r:
            body = json.load(r)
    except urllib.error.HTTPError as e:  # 4xx/5xx：错误信封同样在响应体里
        body = json.load(e)
    if not body.get("success"):
        raise RuntimeError(f"{body['error']['code']}: {body['error']['message']}")
    return body["data"]


data = parse("https://v.douyin.com/xxxxxxx/")
print(data["title"], data["assets"][0]["url"])
```

## 2. GET 形式：浏览器地址栏、简单探测

```bash
curl -sS "$BASE/parse?url=$(python3 -c 'import urllib.parse,sys;print(urllib.parse.quote(sys.argv[1],safe=""))' 'https://v.douyin.com/xxxxxxx/')"
```

**整条链接必须 URL 编码**。小红书分享链接带 `xsec_token` 参数，直接拼在 `?url=` 后面会被服务端当成 `/parse` 自己的参数吃掉，表现出来是解析失败或跳登录墙。`url` 最短 8 个字符，短了直接 400。

## 4. 选清晰度：读 variants

`assets[].url` 是主档位（抖音取无水印 1080p，B 站取服务端最高档，YouTube 优先音画合一的合并档、免合成，无合并档才取最高视频档），其余档位在 `variants[]` 里。`ratio` 是各平台自己的档位标识，实测值：

| 平台 | `variants[].ratio` 实测 |
|---|---|
| 抖音 | `normal_1080_0` / `normal_720_0` / `normal_540_0` / `lower_540_0` / `origin` / `watermarked_720p` |
| B 站 | `720P` / `480P` / `360P` / `1080P`…（按 DASH id 映射，实际档位看服务端返回；`try_look=1` 可拿到 1080P，见 `docs/research/02`） |
| YouTube | `2160p` / `1440p` / `1080p` / `720p` / …（ANDROID_VR 客户端最高可到 4K） |
| 微博 | `1080P` / `720P` / `480P` |
| X/Twitter | 按 bitrate 多档 mp4 |

带 `watermark: true` 的档位是有水印的原片，别当无水印用。

```js
// 按档位挑；挑不到就退回主 URL
function pickUrl(asset, ratio) {
  return asset.variants?.find((v) => v.ratio === ratio)?.url ?? asset.url;
}

// 或者按高度挑一个不高于目标的最高清档位
function bestUnder(asset, maxHeight = 1080) {
  const cands = [asset, ...(asset.variants ?? [])]
    .filter((v) => v.height && v.height <= maxHeight && !v.watermark)
    .sort((a, b) => b.height - a.height);
  return (cands[0] ?? asset).url;
}
```

## 6. YouTube：直链绑出口 IP，必须走中转

`googlevideo.com` 的直链绑定解析时的出口 IP，客户端拿直链直接请求会 403。服务端的处理：**配了 `PROXY_SECRET` 时，`/parse` 会自动把绑 IP 的直链改写成签名 `/media` 链接**，调用方拿到的 `assets[].url` 已经是 `/media?...`，不用自己拼。同一条链接的 `expiresAt` 会落到签名有效期（签发后 600 秒），比直链本身短，这是 `/media` 链接的真实可用期。

未配 `PROXY_SECRET` 时 `/media` 返回 501，YouTube 直链也不会改写，此时客户端拿到直链必然 403。**要用 YouTube 就必须配 `PROXY_SECRET`**，且解析与中转走同一个出口（海外平台代理见 README 环境变量）。

自己拼 `/media` 链接（自建网关、或要复用签名时）的算法：

- `exp` = 当前 Unix 秒 + 600
- `sig` = HMAC-SHA256(`PROXY_SECRET`, `"<原始直链>\n<exp>"`) 的十六进制前 32 位。**HMAC 的输入是原始 URL，不是 base64 串**
- `u` = 原始直链的 base64url（无 padding）
- `title` 可选，给了就带 `Content-Disposition`，浏览器变下载且文件名是标题

```js
import { createHmac } from 'node:crypto';

function mediaUrl(directUrl) {
  const exp = Math.floor(Date.now() / 1000) + 600;
  const sig = createHmac('sha256', process.env.PROXY_SECRET)
    .update(`${directUrl}\n${exp}`)
    .digest('hex')
    .slice(0, 32);
  const u = Buffer.from(directUrl).toString('base64url');
  return `${BASE}/media?u=${u}&exp=${exp}&sig=${sig}`;
}
```

```python
import base64
import hashlib
import hmac
import os
import time


def media_url(direct_url: str) -> str:
    exp = int(time.time()) + 600
    sig = hmac.new(
        os.environ["PROXY_SECRET"].encode(),
        f"{direct_url}\n{exp}".encode(),
        hashlib.sha256,
    ).hexdigest()[:32]
    u = base64.urlsafe_b64encode(direct_url.encode()).decode().rstrip("=")
    return f"{BASE}/media?u={u}&exp={exp}&sig={sig}"
```

`/media` 支持 Range 和 HEAD，可用于边下边播；上游域名走白名单（平台分享域 + CDN 域），跳转每跳重新校验。

## 7. 出错怎么处置

错误一律走信封，`data` 为 `null`：

```json
{
  "success": false,
  "data": null,
  "error": { "code": "RISK_CONTROL", "message": "平台风控，请稍后再试" }
}
```

| `error.code` | HTTP | 含义 | 客户端该怎么做 |
|---|---|---|---|
| `INVALID_URL` | 400 | 链接不合法或太短 | 检查输入，不重试 |
| `UNSUPPORTED_PLATFORM` | 422 | 平台没接入 | 不重试 |
| `UNSUPPORTED_CONTENT` | 422 | 内容类型不支持（如纯文字） | 不重试 |
| `CONTENT_NOT_FOUND` | 404 | 作品删除/私密/ID 不存在 | 不重试 |
| `CONTENT_RESTRICTED` | 403 | 登录可见、地区限制等 | 不重试 |
| `AUTH_REQUIRED` | 424 | 该内容必须登录态 | 不重试（预留码，当前不产生） |
| `RISK_CONTROL` | 503 | 平台风控 | **不要立刻重试**，退避 60 秒以上；风控时重试会加重风控 |
| `UPSTREAM_CHANGED` | 502 | 平台接口改版 | 不重试，等适配器更新（看 `via` 与 `/metrics` 定位） |
| `UPSTREAM_ERROR` | 502 | 上游 5xx / 网络错误 | 服务端已重试 1 次，客户端可再试一次 |
| `UPSTREAM_TIMEOUT` | 504 | 上游超时（单请求 15s 上限） | 可再试一次；持续超时查出口网络与代理 |
| `RATE_LIMITED` | 429 | 超 30 次/分钟/IP，或中转并发满 | 退避后重试 |
| `MEDIA_LINK_EXPIRED` | 410 | `/media` 签名过期（600 秒） | 重新 `/parse` 取新链接 |
| `MEDIA_BAD_SIGNATURE` | 403 | 签名对不上 | 检查签名算法与 `PROXY_SECRET` |
| `MEDIA_PROXY_DISABLED` | 501 | 未配 `PROXY_SECRET` | 直链路径不受影响；要中转就配密钥 |
| `CONFIG_MISSING` | 501 | 缺必要配置（如 `IG_GRAPHQL_DOC_ID`） | 补配置后重试 |
| `INTERNAL` | 500 | 服务内部错误 | 带响应头 `x-request-id` 查日志 |

```js
const RETRYABLE = new Set(['UPSTREAM_ERROR', 'UPSTREAM_TIMEOUT', 'RATE_LIMITED']);

async function parseWithRetry(url, { retries = 1, backoffMs = 1000 } = {}) {
  for (let i = 0; ; i++) {
    try {
      return await parse(url);
    } catch (err) {
      if (i >= retries || !RETRYABLE.has(err.code)) throw err;
      await new Promise((r) => setTimeout(r, backoffMs * 2 ** i));
    }
  }
}
```

风控类错误别放进重试白名单。`RISK_CONTROL` 反复出现时：抖音检查 `DOUYIN_UIFID` 是否过期（L2 签名通道靠它），小红书与抖音都要确认浏览器兜底可用（`BROWSER_FALLBACK` 未设成 `off`）；`via` 字段会如实标出这次走的通道，`/metrics` 的 `channel_downgrade_total` 与 `channel_breaker_open` 能看出是不是在降级。

## 8. 限流与并发

- `/parse` 按 IP 限流 **30 次/分钟**（令牌桶，桶容量 30）。反代后面用 `X-Real-IP`，其次 `X-Forwarded-For` 第一跳，都没有才用连接地址。nginx 之类的反代记得注入 `X-Real-IP`，否则所有请求共用一个桶。
- 超限返回 429 `RATE_LIMITED`，退避后重试即可，桶是按时间补充的。
- `/media` 中转并发上限 2，满了直接 429（不排队）。中转走服务器带宽，别拿它跑批量下载。
- 批量解析建议并发 4 以内并复用缓存结果；同一条链接重复解析命中缓存，不消耗上游请求。

## 9. 特殊客户端：必须带 Referer 的容器

微信内置浏览器、部分 App WebView 会给请求强制加 Referer，导致直链被 CDN 拒。这类场景把直链换成 `/media` 中转链接（配置 `PROXY_SECRET` 后，YouTube 已自动改写；其他平台的直链可自行按第 6 节算法签名），中转由服务端控制请求头。需要固定下载文件名时，在 `/media` 链接上带 `title=<标题>`，响应会带 `Content-Disposition`。

## 10. 排查用

| 想看什么 | 怎么查 |
|---|---|
| 这次走的哪条通道 | 响应 `data.via`：`http` / `http-l2`（抖音签名通道）/ `browser`（浏览器兜底） |
| 是不是命中缓存 | 响应顶层 `cached` |
| 平台是否在降级 / 熔断 | `GET /metrics` 的 `channel_downgrade_total`、`channel_breaker_open` |
| 各平台成功/失败分布 | `GET /metrics` 的 `parse_total{platform,code}` |
| 服务活不活、平台注册齐不齐 | `GET /health`、`GET /ready` |
| 支持哪些域名与能力 | `GET /platforms` |
| 一眼看全状态 | 浏览器打开 `http://<服务器>:7777/status` |
